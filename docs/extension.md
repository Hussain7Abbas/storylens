# Browser extension

[Documentation index](intro.md) · [Development](development.md)

The WXT Chrome/Firefox development server uses port 3050, leaving port 3000 for the website during `make dev`. This is separate from `WXT_API_URL` and the `WXT_WEBSITE_URL` account-bridge origin; the development manifest's CSP follows WXT's resolved server port.

`apps/extension` is a WXT and React extension for Chrome and Firefox. The popup lets readers manage novels, keyword coloring, replacement rules, and settings. Coloring lists keyword groups by creation date, newest first, on every open and when searching; editing a keyword keeps its position. Settings tab labels size to their content and wrap onto another row at narrow widths. The Profile menu item opens the account pages on the website. The content script detects supported pages and applies reading features; the background service worker handles messaging, selector loading, API proxy requests, and synchronization.

The popup opens on **Coloring**. **Settings → AI** selects text and image providers independently: **Text AI provider** chooses **Story Lens Cloud** or **Desktop companion** (`storylens-ai-source`), while **Image generation provider** chooses **Story Lens Cloud** or **Desktop (Codex)** (`storylens-ai-image-source`). Until the first provider change, an older install keeps its previous shared choice; changing text preserves that image choice. Existing configured pairings default to Desktop; other installs default to Cloud. Cloud requires a registered account and enabled pricing records. Its panel shows account status, availability, balance, feature prices, the processing disclosure and a privacy link. Desktop keeps the shared port/token pairing and discovered Claude/Codex/Gemini CLI text model and effort. Desktop images use the default Codex model and effort independently, including when text uses Cloud or Gemini. Optional novel research follows the text provider; price badges and image availability follow the image provider. The five shared **AI prompts** are edited only in dashboard **Settings → AI**. Before constructing a new keyword, character-image, chapter-cover, chapter-context or page-summary prompt, the extension asks its background for `GET /api/user/ai/instructions`. The last successful templates are cached under `storylens-shared-ai-prompts`; offline use or an older API keeps that snapshot, or bundled defaults when no snapshot exists. Legacy local `storylens-ai-prompts` overrides are ignored. Shared instructions apply to Cloud and Desktop and precede chapter text and novel context.

`src/lib/ai-source/` owns source selection, shared availability and the localized prompt runner; `src/lib/cloud-ai/` owns background fetch, bounded NDJSON/JSON response parsing and serializable failures. Cloud sends the extension's feature-keyed prompts to `/api/user/ai/prompts` or `/images` with bearer auth, language and client-version headers. One action ID spans the first attempt and one free JSON/validation/language correction. A failed correction retains a usable paid first answer. Jobs have owner-scoped cancellation and absolute 180-second text / 300-second image limits. The background keeps the MV3 worker active during a bounded job, persists frame balances, and refreshes the authoritative balance after completion. A 426 triggers the normal extension update check; an older API's 404 shows Cloud unavailable without changing the selected source.

Cloud summaries send cleaned visible page text with block breaks and refuse oversized prompts instead of truncating them. Scripts, forms, controls, hidden content and extension UI are removed. Desktop summaries retain cleaned HTML and the 500 KB limit. **Auto-detect from current tab** sends the URL and a bounded page outline through the selected source, validates the suggested selectors against the page and permits one correction on the same action ID. New extensions never call the deprecated raw-HTML selector route or silently switch providers. Suggested selectors still require the reader's review and manual save.

The navbar contains the brand, account lens balance, Sync status, **⋮** menu and Back on subpages. The menu holds Refresh, Theme, Language (hidden for moderators), Profile and Settings (hidden on Settings). The balance chip opens `/{locale}/profile/balance/?from=extension#request`; a guest's chip opens registration. Prices appear on AI controls only for Cloud and positive prices, using the coin and localized accessible label. A refusal for insufficient lenses opens Balance with `need`, `feature`, `from=extension` and `#request`; the manual form remains available with **Get lenses**.

Lens coins keep their original static full/small/mono SVG and add three CSS sparkles that brighten at 300 ms offsets, each repeating every 900 ms. The React component in `src/lib/lens-coin/` mirrors the canonical [branding source](branding/README.md#lens-coin); non-React launcher and summary badges use `createLensCoin` and `LENS_COIN_MOTION_CSS` in `src/lib/lens-coin.ts` for the same decorations in shadow roots. Price layout remains fixed, mono uses `currentColor`, hover/focus pauses the sparkle opacity, and reduced motion or forced colors hide the decorations. No player, timers or remote animation code is loaded.

`src/lib/billing/` caches public pricing for 10 minutes on popup open and 30 minutes before an action. Failed refreshes keep the last copy. Balances and notices are account-scoped; another account's values and late responses are ignored. Trial/admin gifts and purchases from `surface=extension` open one combined congratulations modal in the main popup only. A short background lease prevents duplicate simultaneous popups, and successful acknowledgement removes those notices. Refunds and adjustments never celebrate. Confetti loads only for an opened notice modal and is skipped with reduced motion. First install opens the locale-matched website profile with `from=install`; updates do not open a tab. The website bridge can then share its session.

The desktop path remains free of Story Lens lens charges and uses the reader's own provider account. After a successful connection and on sign-in/sign-out, `shareAccountSession()` still sends the API URL and session token (or `null`) to the client for its [wiki crawler](client.md#wiki-crawling). See the [client guide](client.md) for setup and execution limits.

On a page whose domain has a website selector in the novel-site database or extension cache, a circular logo button on a neutral surface with an iris focus ring appears in the top-right corner by default. Drag it to move it; its position is saved in extension-local storage (`storylens-page-launcher-position`) across sites and reloads. Saved and dragged positions are clamped to the viewport, including after resizing. Within 10 px of the nearest viewport edge, the idle circle tucks against that edge with 3 px visible; moving the pointer within 10 px reveals it at its saved position. When the launcher appears (page load, or Show turned on), it stays fully visible for 3 seconds before tucking, so readers can find it. Dragging, keyboard focus, and an open popup keep it visible. **Settings → General → In site popup** controls Show/Hide, defaults to Show, and is saved in extension-local storage (`storylens-page-popup-visible`) with immediate updates across tabs. It opens the same extension popup in an overlay iframe; readers can use either this button or the browser toolbar icon. The popup chooses the available side and vertical direction, shrinks to fit the viewport, and scales its contents when narrower than the normal popup width. Inside the overlay, the popup fills the whole iframe instead of using the toolbar popup's fixed 24rem × 32rem size, so the tab panels reach the bottom of the overlay. The launcher is removed when the selector is unavailable and closes on circle click, outside click, Escape, or navigation; there is no separate close-button bar. Closing only hides the popup: its tab, search text, open form and any running AI request continue, and opening the launcher again shows them as they were. A reader can start **Generate image**, close the popup to read, and come back to the finished image in the form. The popup page and launcher icon are listed as web-accessible resources. The selected extension language is also sent as `responseLanguage` with each desktop AI request.

While the popup is closed, a dot on the launcher shows its AI requests: a pulsing iris dot while one runs (steady with reduced motion), then a green dot when the result is ready or a red dot when it failed, until the popup is opened. A finished request also brings a tucked launcher back from the viewport edge, and the launcher's label carries the same state. The kept popup is replaced only when that loses nothing:

- Picking text or pressing a tooltip **Edit** button asks the shown popup tab for the requested form. A tab without unsaved work loads it. When the tab still holds unsaved work (edited fields, a picked or generated image that is not saved, an AI result in the form, or a running AI request), it stays as it is and the requested form opens in a new tab. Up to 6 tabs are kept; past that the notice "Save or close one of the open forms first." appears. An untouched form is replaced. The tab itself answers this, from what it holds at that moment, so an edit made just before the request is never lost.
- Tabs out of sight that hold nothing (a saved or closed form, an untouched one) are removed when the panel closes or another tab is shown, after they answer that they hold nothing; a tab whose AI result or failure the reader has not looked at yet stays.
- After an in-site navigation, the launcher asks the popup whether it holds unsaved work. One that holds none is removed, so the next one detects the new page. One with unsaved work is kept, and asked again each time it is closed, until that work is saved or closed.
- Values a form fills in by itself (a saved selector, a detected novel name) do not count as unsaved work, unless the reader already edited the form before they arrived; a field the reader already changed is not replaced by a late detected value.
- A full page load (reload, or a link that loads a new page) and hiding the launcher in settings remove the popup with its state. The toolbar popup is closed by the browser and never keeps its state.

Popup tabs and AI requests are listed under the launcher, without hovering it. Each popup tab is a card, so the reader can run several AI requests at once (pick one character, let AI fill it in, pick the next, generate images in each) and switch between them: clicking a card shows that tab in the panel, and the current tab, which the launcher button opens, is marked with an iris edge. With one tab, its card appears only while it has AI requests. A tab's card shows its latest AI request: a spinning icon and "{name} - {operation}" while it runs, a green check when it is done, and a red cross when it failed. The name is the selected text (keyword suggestion), the form's name (image generation), the page title (summary), the novel (chapter extraction) or the site (selector detection); a request without one shows the operation alone. Cards follow the launcher's side like the action row (below it in the top half of the viewport, above it in the bottom half) and move past the action row while it is open. They hide while the popup or chooser is open. A tab without AI requests is named after its form ("Rand - New keyword", "Edit alias") or "Story Lens". A finished request on a tab's card stays until that tab is shown; a finished summary or extraction card leaves after 8 seconds; a cancelled request (its form closed) leaves at once. While cards are listed the launcher does not tuck.

Leaving or reloading the page asks for confirmation (the browser's own "Leave site?" prompt) while an AI request runs, while an AI result has not been saved (a form AI filled in, a generated image, extracted rows not saved yet), or while the popup holds unsaved changes. Summaries have nothing to save and do not ask once they finish. Saving or dismissing the last character form clears its keyword suggestion and releases its AI task, even though the Coloring tab stays mounted. In-site navigations do not trigger the prompt.

Popup and chapter-panel frames report their requests with `useAiTask()` (`src/lib/launcher-frame/use-ai-task.ts`) through the background (`reportAiTask`, relayed to the tab's content script as `aiTaskUpdated`), so names never pass through the novel site's window; the summary reports to the content script's list (`pageAiTasks` in `src/lib/launcher-frame/ai-tasks.ts`) directly. A frame's requests end with its frame: removing or reloading the popup and closing the extraction panel drop them. This also covers a popup that reloads itself after saving selectors: its new ready key releases the previous document's tasks without affecting other tabs, summaries, or extraction.

Hovering the launcher for 0.2 seconds reveals four 44px actions: **+**, **Summarize page**, **Extract chapter characters**, and **Night light**. They hide after 0.3 seconds away and appear on keyboard focus. Summarize and Extract explain the selected source’s account, feature or pairing restrictions; priced Cloud actions show live coin badges. Action buttons have localized tooltips.

**Night light** lays a yellow layer over the whole page for reading at night. The action is a toggle: it shows a moon and "Turn on night light" while off, a sun and "Turn off night light" while on, and the action row stays open after a click. The layer (`src/lib/night-light.ts`) is a fixed, click-through element appended after `<body>`, so it also covers the launcher, its popup and the keyword tooltips, and it multiplies the page's colors instead of covering them, so a dark page stays dark. The on/off state (`storylens-night-light`, off by default) and the level (`storylens-night-light-level`) are saved in extension-local storage, shared across sites, and applied immediately in every open tab. **Settings → Appearance → Night Light** sets the level with a horizontal slider from 10% to 80% in steps of 5 (default 30%); a stored value outside that range is clamped. The layer belongs to the launcher: it is shown only on pages where the launcher is, and hiding the launcher removes it while keeping the saved state. It does not cover the full-size image modal or a fullscreen element, which the browser draws above the page, and it appears on a newly loaded page only once the launcher does.

The single **+** starts a disposable text picker: click a word or drag a phrase, then choose **Keyword**, **Alias**, or **Version** in an icon-button panel above the selected text (clamped to the viewport). The panel embeds `popup.html?view=selection`, asks for a novel if detection cannot resolve one, and offers adjacent **Use AI** and **Generate Image** switches, both off by default with either source. **Generate Image** can be toggled only while **Use AI** is on and the image provider can generate images; switching AI off clears the image choice. Each Cloud switch shows its own lens price. Unavailable AI explains the selected source’s restriction and continues manually. Alias and Version require a parent keyword from a debounced fuzzy searchable dropdown; it reads the novel's local view (pulling the novel first when the device has no copy), including alias names in matching. Changing the novel clears the parent.

Continuing opens the corresponding full-page form, seeded with selected text (without Arabic diacritics, as it will be saved) and the chosen novel/parent. With **Use AI** on, the main popup does not open: the form loads in a new popup tab out of sight, and a card under the launcher shows "{text} - Generating keyword" with a spinner while AI writes the details. With both switches on, keyword suggestion and image generation start concurrently after sharing one novel-context lookup; the image uses the selected text, nearby passages and the reader’s image prompt. The launcher tracks both tasks and waits for both to finish. A successful image becomes the form’s selected file and uploads only when saved; either successful result is kept when the other action fails, with an error and the manual image retry available in the form. Optional novel research preserves enough lenses for both actions. When the requests end (done or failed), that tab opens by itself beside the launcher with the form filled in (or empty for a manual entry after a failure), unless the reader is using a popup, the chooser or the text picker at that moment; then the card stays with its check or cross until the reader clicks it. Clicking the card earlier shows the form while it loads, and it then never opens again by itself. At the six-tab limit the form opens the usual way. A form whose AI request never starts within 8 seconds opens anyway. AI uses up to 1,500 nearby characters on either side via the hidden `aiContext` parameter, then suggests description, category and nature in the extension language, and for a keyword or alias also looks for a **Link** among the novel's entries named in the other language and not in the reader's (at most 150, with trimmed descriptions): a keyword form is offered other keywords, an alias form the parent keyword's other aliases, and a match opens the form with that tab already linked. Alias/version descriptions retain their parent note. Guests cannot create entries. Escape, outside click, close and disposal clear selection guards and iframe message listeners; the launcher accepts chooser messages only from its own iframe window and extension origin. Temporary page copy-protection overrides exist only while selecting.

Opening a highlighted word’s tooltip (`src/utils/keyword-tooltip.ts`) shows: an **Info** panel, plus **Aliases** and **Versions** tabs when the character has visible rows in the current UI language. Aliases require a nonblank name in that language and never fall back to the other language. Versions retain the base and shared image/style-only rows, while hiding nonbase versions described only in the other language; bilingual descriptions show only the selected language. Empty alias tabs and version tabs with only one remaining row are omitted. These display filters preserve downloaded data and highlight/image inheritance. On an alias the image is the alias's own, whatever its style override says; an alias without an uploaded image inherits the version being read, then the latest other version that has an image, then the base version. So a character whose image was uploaded on any version is never shown without one, and the show-more under the image names each image it replaced (an empty step as "—"). The **Aliases** and **Versions** rows each carry a thumbnail of their own image, or the inherited one dimmed, the same way the popup's Coloring list shows its keyword, alias and version cards. Tooltip images, including the provenance and row thumbnails, are buttons: clicking one closes the tooltip and opens the image at full size in a modal centered on the page (`src/utils/image-modal.ts`, a `<dialog>` sized by the image and capped to the viewport), closed by its close button, Escape, or a click outside it. Its image remains a native interactive `<img>` with the original URL, supporting the browser’s Copy image, Copy image address, Save image and other image context-menu actions. Scoped event handling protects those native actions from page handlers while the viewer is open. The keyword's **Edit** button floats beside the tooltip at the edge nearest the word, above **Generate image with AI**, and each alias and version row keeps its own Edit button in its panel; they open the launcher popup directly on that edit form (`popup.html?edit=keyword|alias|version&id=…&parentId=…&novelId=…`, read by the Coloring tab). Edit buttons appear only for rows the signed-in reader may change (the same per-row rules as the popup cards, which the Coloring tab checks again before opening a form) and only while the launcher is shown, since it hosts the form. The Coloring tab handles a form request from the URL once (an `edit` request, or a `create` request from a text pick) and then removes its parameters, so leaving for Settings or Sync status and coming back does not reopen the form.

Opening a word’s tooltip shows **Edit** above **Generate image with AI** in an action box attached to the tooltip at the edge nearest the word. Both boxes stay together on the side of the word that fits (above by default), with the action box between the details and the word: below the tooltip when above the word, above the tooltip when below it. The tabs stay at that same edge, outside the scrolling details, and support arrow keys, Home and End. Near the top both boxes flip together below the word. Placement reserves space for both boxes, keeping them 8 px inside the viewport and clear of the word. When neither side fits the full tooltip, it uses the side with more available space and scrolls the content inside the tooltip; the arrow stays visible and the scroll position survives page/layout changes. Widths are bounded to the viewport and the action label can wrap on narrow windows. Image loads, tab changes, font changes and window resizing remeasure the layout. Each action button has its own surface and shadow, with a transparent container between them. The container and row gaps remain part of the shared hover area, so moving across the transparent space between buttons keeps the tooltip open. In hover mode, moving the pointer between the word, the tooltip and the action keeps everything open; in click mode, the tooltip stays open across pointer movement. The action appears under the same conditions as **Edit** (the launcher is shown and the reader may change that character). Clicking it opens the character's form in the launcher popup with its AI image request already running (`popup.html?edit=keyword&…&generate=image`), as if the reader had pressed **Generate image** there: the launcher card shows the progress, and the drawn image is saved with the form like any other. The form also opens when automatic generation is unavailable, so its image prompt can still be copied; it shows the reason without sending an image request.

The tooltip also offers **Add alias**, **Add version**, and **Add replacement** for signed-in readers, including on another reader's keyword. Add alias/version open forms with the hovered keyword already selected as parent. The sparkle beside Add alias lets the reader click a word or drag a phrase on the page to fill the alias name before reviewing and saving the form. Add replacement (or its sparkle) picks the source text and saves a full-word replacement immediately, using the canonical keyword name in the selected language as the target; no form opens. The background validates the sender, top frame, detected tab novel and bounded text, derives the target from its local view, and saves through the offline outbox before refreshing that tab. The replacement works offline and syncs later. Notices confirm saving or explain a refusal; a lost refresh still reports that the replacement was saved. Escape, navigation, hiding or disposing the launcher cancels a pick and removes its selection guards. Tooltips are suppressed while picking, and extension UI and editable controls cannot supply picked text.

**Info** resolves aliases’ own description, category and nature first, regardless of the legacy style-override flag. Missing fields inherit independently through chapter versions, newest applicable to oldest, in the selected language. Overlapping ranges select the greatest starting chapter, not the API’s array order; range gaps retain the nearest earlier version. An alias’s missing name uses the keyword name in that language. Its own image wins, followed by the active version, latest other version with an image and base. Highlighting, popup alias cards and tooltip alias rows share this inheritance. **Original** remains the base keyword’s information and appears only for aliases or a distinct active version.

**Settings → Appearance → Show tooltip** is a segmented control with **On hover** and **On click** (the default). It saves `storylens-tooltip-trigger` and updates existing reading tabs immediately, dismissing an open tooltip when the mode changes. On click opens a keyword or alias tooltip and keeps it open until the same word is clicked again, the reader clicks outside, or Escape is pressed. Enter/Space toggles a focused keyword in either mode. On hover keeps the shared hover group and delayed dismissal. Both modes are suppressed while picking text. Appearance also sets the tooltip font and its size. The size is a horizontal slider from 18px to 42px (default 24px), saved as `storylens-font-size` and applied to open tooltips at once. A saved size outside that range falls back to 24px, including the old 14px default; previously selected sizes from 18px to 22px remain valid. The tooltip has a fixed 420 px width, capped to the viewport with 8 px side margins. Font changes resize the text within that box. All text wraps, including long names, descriptions, metadata, tab labels and inline edit buttons; images also fit within the available width. Both Appearance sliders use `components/level-slider.tsx`, which can be dragged, clicked or moved with the arrow keys. Values increase to the right in English and to the left in Arabic.

Novel and keyword names are translated (`nameAr`/`nameEn`, novels also `descriptionAr`/`descriptionEn`), and the extension shows only the UI language's fields: an English UI lists and highlights only novels and keywords that have English names, and hides the rest. Requests carry the UI language as `Accept-Language` so the API filters online lists. The novel catalogue and downloads fetch both languages, and every local read filters by the current one, so switching language works offline. Forms edit and create the current language's name and description only; **Add novel** on a page whose slug an existing novel already has fills that novel's missing translation. Page highlighting matches the UI language's names and re-runs when the language changes. Popups read the saved locale before their first render, so opening the launcher does not briefly switch an Arabic page to English. Highlight refreshes keep existing colors until replacement data and chapter content are ready; only the newest request for the current page URL may replace them. Missing data or a failed request leaves existing highlights intact. The offline-first update starts with a fresh local database: earlier downloads and unsent edits are not migrated and readers must download novels again. Alias name script detection uses letters only, so Arabic-Indic digits alone do not count as an Arabic name.

Arabic keyword and alias forms show **Fuzzy Match Arabic Characters Variants** below **Full word match** when the edited name contains Arabic letters. It defaults to on, including for existing rows: page highlighting treats ا, أ, إ, آ and ٱ as interchangeable, while leaving the displayed page text untouched. Turning it off distinguishes those letters; canonically equivalent composed and decomposed hamza spellings still match. The switch applies independently of full or partial word matching and is stored per keyword or alias. It does not fold ى/ي, ة/ه, or hamza on و/ي. Replacement rules keep their existing matching behavior.

Arabic matching always ignores diacritics (حركات): tanween, the short vowels, shadda, sukun, the dagger alif, Quranic marks and tatweel (`src/utils/arabic.ts`, the same set as the backend; hamza and madda marks stay because they form letters). Keyword, alias and replacement terms match page text whatever diacritics either side carries, including after the ال and single-letter prefixes, and the highlight keeps the page's own marks; a word that continues with a mark still fails a full-word match. Keyword and alias names are saved without diacritics (`enqueue` strips them like the API, so a name differing only in marks counts as taken or unchanged), searches and AI name comparisons (chapter extraction, image passages) compare letters only.

Create, edit and delete forms occupy the entire content region beneath the navbar. The novel selector, warnings and tab controls are hidden while a form is open. Navbar **Back** closes the form and restores its originating page and selected tab. `components/form-page.tsx` preserves underlying page state while rendering the form through a shared portal.

**Extract chapter characters** places a panel at the start of the chapter content (the same content root highlighting uses). It embeds the extension page `popup.html?view=extract`, which resizes the panel through `postMessage` (the panel accepts messages only from its own frame). The page detects the novel, or asks the reader to choose one, reads up to 120,000 characters of chapter text from the content script (skipping scripts, hidden elements, and extension markup), and sends it with every category and nature description and the novel's known character and alias names to the selected AI source. Cloud checks the complete prompt against the feature’s limit before sending. The answer becomes a table of editable **Name** and **Description** text fields, **Category**, **Nature**, and **Parent** selects (Parent searches every character of the novel, including alias names, with fuzzy matching), and per-row **New**, **Alias**, **Version**, and **Ignore** buttons. Names the novel already has are dropped. When the AI suspects a new name is another name (`alias`) or a later form (`version`) of a known character or of another row, it returns that parent: the row preselects it in **Parent**, shows a localized “AI: probably …” note, and fills the matching **Alias** or **Version** button while making **New** secondary. A suggested parent that is another row links up as soon as that row is added (its client ID is known at once); choosing or clearing the parent by hand stops applying the suggestion. **New** creates the character; **Alias** and **Version** are enabled once a parent is selected, and add the row under that parent with the same parent note as above (a version starts at the detected chapter). **Ignore** removes the row. Saves go through the offline-first mutation hooks and refresh the page's highlights. Navigation or the panel's **Close** button removes it.

Every novel has an optional **context** (genre, setting, power system, premise, main characters, tone), editable in the novel form. Keyword suggestions, chapter extractions and image generation add it to their prompts. When it is empty, the first of these AI actions asks the selected source to research the novel with web search (`ensureNovelContext` in `src/lib/desktop-client/novel-context.ts`), saves the answer through `PUT /api/user/novels/:id/context`, and updates the downloaded and catalogue copies; a failed, offline or unaffordable research continues without context. Optional priced Cloud research preserves the cached budget for the parent action, and an already-created context is reloaded after a concurrent research refusal. Readers can fill a missing context; only moderators (roles with `user:moderate`) and the dashboard can change an existing one, so the form locks the field for other roles.

The keyword and alias forms are split into two language tabs, **AR** and **EN**. The reader's own language opens first, and each tab holds that language's **Name** and **Description**, plus the shared matching, category, nature and image (and an alias's style override). Editing a shared style field shows in the other tab, while names and descriptions stay independent. The same active panel is reused, preserving shared controls and ongoing image generation when tabs change. An empty tab saves no name for its language; at least one name is required, as the API asks.

The other language's tab begins with an optional **Link** (`src/components/translation-link-select.tsx`), a debounced fuzzy dropdown over the novel's local view. Readers used to write only their own language, so the two languages of one character often ended up as two entries; linking them says they are the same entity. It offers the novel's keywords named in that tab's language and not in the reader's — for an alias form, the parent keyword's other aliases by the same rule, since an alias never moves between keywords — and excludes candidates that conflict with the saved row’s stored name in that language. The outbox checks whether the reader may absorb the chosen row before accepting a save. Choosing one fills that tab's **Name** (which is then shown read-only, because it belongs to the linked entry until the merge moves it) fills that language’s **Description** and overwrites the shared category, nature and image from it, because saving merges the two rows into the one being saved: it takes that language's name, and a keyword also takes the linked keyword's aliases, chapter links and replacements, after which the linked row is gone from both languages. The form sends the link rather than the name it is showing, since the row being absorbed still holds it. A tab holding a link is marked on its label. Clearing the link restores that tab's stored name and leaves the style as it is.

Keyword, alias and version image inputs share a **100px drag-and-drop uploader** (`src/components/image-upload.tsx`). Drop one image or click the centered upload area; Enter/Space opens the same native file picker. The border responds to hover, keyboard focus, accepted files and rejected drops without changing the area’s height. A selected image shows its filename (or a saved-image label) and a **Delete image** button; the preview stays below the AI prompt controls. Images are limited to 10 MB, with localized validation for file type, size and multiple files; rejected files preserve the current selection. Deleting removes a newly selected/generated file or clears the saved image through `imageId: null` when the form is saved. Arabic layouts, dark mode, reduced motion and coarse-pointer delete targets share the same component.

The keyword, alias and version forms have a **Generate image** button and an initially collapsed **Image Prompt** section (`src/components/generate-image-button.tsx`, `copy-image-prompt.tsx`), with a 100px editable preview, a bottom gradient and Expand control, and a copy icon at its top end. AI keyword suggestions and extraction prepare missing prompts, combining visual details with the shared image instructions and chapter/novel context. A manual image run prepares a prompt only when empty: it uses the active language tab’s name (the parent keyword’s for versions), chapter passages mentioning its names, description, category, novel context and dashboard Settings → AI instructions. Subsequent runs send the saved or edited prompt unchanged; changes to other form fields do not rebuild it. Generating with an empty prompt asks whether to Extract With AI (the normal character-generation price, with any first-time research cost disclosed) or provide a prompt manually. Extract continues generation from the current chapter; the manual choice opens, expands and focuses the editor without AI. Missing chapter text fails before an image request. Copy is disabled for empty prompts. A copied or generated prompt is saved with the entry through the offline queue. The textarea remains selectable but read-only during image generation; Copy remains available for the submitted text, including after success, failure or Stop. Clipboard failures leave the editable text available for manual copying.

**Stop image generation** cancels preparation/research or the image request, clears busy state and retains the previous image and prompt. Late results cannot replace the image or restart the run. Selection-started images have their own Stop action, independent of the concurrent text suggestion. An unavailable image source leaves saved prompts copyable and offers manual input without an AI request. The Cloud provider’s revised prompt appears separately in **What was drawn**. First-time paid novel research is disclosed in the tooltip. The result becomes the form’s selected file; saving queues it and uploads it first through `POST /api/user/files/upload` to image storage (imgbb). Toolbar and launcher popups use the same path with owner-scoped cancellation. A form opened by the page’s **Generate image with AI** action starts once when its name and selected source are ready.

All AI answers (summaries, suggestions, and extractions) are written in the extension language. Every prompt carries an explicit language rule, and when the returned descriptions are mostly in the other script (Arabic vs Latin letters), the request is repeated once with a correction. Cloud uses the same action ID so this correction does not charge again.

Character and replacement searches tolerate small spelling mistakes and transposed letters while retaining partial-text matching. Character search includes alias names (their Arabic and English translations too) and version descriptions; replacement search includes both From and To. Searches run over the novel's local view, online and offline. Add character and Add alias prefill Name from the trimmed search; Add replacement prefills From. Versions have no separate name, so Add version prefills Description. Existing edit forms keep their saved values.

## Account and synchronization

The popup creates a guest account on first open and stores the session in `browser.storage.local` (`storylens-auth`). Sign-in, registration, profile edits, email and password changes, and sign-out live on the website's `/{locale}/profile/` pages, not in the popup: browser password managers such as Apple Passwords cannot fill forms on `chrome-extension://` pages. The popup's profile button opens that page in a new tab.

The `website-bridge` content script runs only on the `WXT_WEBSITE_URL` origin (default `http://localhost:3000` in development and `https://storylens.iscoded.com` in production builds). Its registration pattern omits the port for WXT compatibility, and an exact-origin guard runs before listeners or storage reads so other ports cannot exchange session tokens. `test/website-origin.test.ts` checks the WXT matcher and origin boundary. The profile button and the settings website, privacy, and terms links use the same origin through `websitePageUrl`. It answers `window.postMessage` requests on the `storylens-account` channel: `get` returns the stored session, `set` validates and stores a session from the page, and `clear` removes it. It also pushes storage changes to the page. Its protocol lives in `src/lib/website/account-bridge.ts` and must match the website's `src/lib/account/bridge.ts`. Open extension pages follow `storylens-auth` changes through `useAuthInit`. After sign-out, the next popup open creates a fresh guest, as before.

The stored user carries `isGuest`, its `role` and the role's `permissions` from `/api/user/auth/me`. `userAccessAtom` reduces them to an access level for the UI: guest, reader, or moderator (the role holds `user:moderate`). Per-row edit rights mirror the API in `src/lib/auth/permissions.ts`: keywords and replacements are changed by their creator or a moderator; aliases and versions by their own creator, the parent keyword's creator, or a moderator (decision D12). Cards a reader may not change open no form and explain who can. A stored session that no longer parses but still has a token reloads the user from `/auth/me` instead of becoming a guest.

### Offline-first engine

Every screen reads a **view** and every change goes through the **outbox**, online or offline; being online only changes how soon a change is sent.

- **Snapshot:** tables in the IndexedDB database `storylens` holding the rows the server last returned (novels, keywords, aliases, versions, replacements, categories, natures, chapter biases). Only pulls and push outcomes write them, inside the runner's lock.
- **Outbox:** the `mutations` table. `enqueue()` is the only writer from the UI: in one transaction it checks the signed-in account and the per-row permissions, validates against mirrors of the server's rules (unique names per language, version order, protected base versions, lookups in use), keeps only the fields the form changed (with the values the form started from and the row's `updatedAt`), folds the change into an unsent one for the same entity, and records dependencies. IDs are client UUIDs, so nothing is remapped when a create syncs. Once a form closes as saved, the change survives closing the popup, a worker restart and going offline. An explicit delete supersedes refused or conflicted unsent edits of that row; deleting an unconfirmed create cancels its local change and dependants rather than leaving a blocked delete behind.
- **Views:** the snapshot with the signed-in account's unresolved changes applied (`projection.ts`, pure): a new keyword gets its base version, deletes cascade, versions auto-close, replacement chains rewrite, a **Link** merges the linked row away (the saved row takes the names it lacks, a keyword also takes its aliases and replacements), and categories and natures are embedded from the projected lookups. Page highlighting reads the same view through the background (content scripts never open the database). Popups refresh when another context writes the database (Dexie `storagemutated`, with a change-counter check as fallback).
- **Runner** (`sync/runner.ts`, background only): under the `storylens-sync` Web Lock it recovers expired leases, checks the session and the API's sync protocol (`GET /api/user/sync/protocol`, version 2), then sends the outbox one change at a time, in order per entity and after the creates they depend on, each request with a 20 s timeout and the change's own account token. Outcomes follow the API's codes: stale writes (409 `STALE_WRITE`) merge per field automatically and conflict only when both sides changed the same field; deletes win and a 404 on delete counts as done; duplicates, missing parents, rule and permission refusals need the reader; a sent **Link** drops the merged row from the snapshot and marks the novel for a pull, since the server also moved its replacements; 401 and 426 pause the runner without counting attempts; network errors, 5xx and 429 back off (5 s doubling to 15 min, jittered, honouring `Retry-After`) and never exhaust a change. Runs are triggered by `syncKick` after saves and on popup open, a 5-minute alarm (created only when missing), a retry alarm at the next due change, browser start, updates, the worker's `online` event and sign-in changes. Changes made while signed in as another account are held and never sent with this account's token.
- **Pulls** (`sync/pull.ts`): lookups and downloaded (pinned) novels refresh when older than 10 minutes (all of them on **Sync now**), cached novels when a page or the popup uses them (the page gets local data at once and refreshes when the pull lands), the catalogue on popup open when older than 30 minutes. An explicit refresh request pulls a fresh cached novel immediately. Full pulls use complete repeatable-read snapshot endpoints for a novel, lookups or the catalogue; each returns both languages and a cursor from the same database snapshot. After a first full pull, units refresh from the API's change feeds (delta pulls from a cursor), with a full pull again for an expired cursor or once a week. Pulls replace server rows in one transaction and never drop local changes; a pending update of a row the server deleted becomes a `deleted` conflict. Tabs showing a changed novel re-run highlighting.

The navbar's sync button is always visible: its icon shows synced, pending (with a count), sending, offline, paused or needs attention, and its popover shows the last sync time, counts, pauses (**Sign in again**, **Update required**, "Sync paused until Story Lens updates" when the API is older than this build) and **Sync now**. A successful manual sync reports sent changes, or says everything is up to date when none were sent; the number of refreshed data units is not presented as a count of changed items. A failed pull reports that some data could not be checked and stays visible in Sync status until that unit refreshes successfully. Conflicts, held changes from another account, refresh failures and runner errors never display as fully synced. **View sync details** is always available in the popover; the status page also offers **Sync now** and account recovery. The toolbar badge counts the account's unresolved changes (orange pending, red needs attention, grey `!` offline).

After a database reset, the extension may still show its locally stored account while its server session no longer exists. **Sign in again** opens `/{locale}/profile/login/?reauth=1` on the configured website and requests a fresh reader bearer session through the account bridge, including when the website is already signed in. Account pages validate the stored bearer session and automatically use the signed-in website account after a 401, including when the stored account ID is obsolete; only a valid different account needs the account-choice buttons. Website cookies and dashboard sessions cannot authenticate sync directly. Local queued changes remain saved and tied to their original account.

The **Sync status** page (from the popover, card badges or toasts) names each change's novel, parent keyword for aliases/versions, chapter range, requested operation and server refusal, retaining local labels when server rows disappear. It lists changes that need the reader, grouped as **Needs attention**, **Made while signed in as …** and **Waiting to sync**. Stale conflicts show a table of each field's yours, theirs and original values with **Keep mine** / **Use theirs** per field or for all; deleted rows can be discarded or created again; duplicates and refused rules have an **Edit** control to fix the name or chapter inline, plus **Retry** and **Discard**; delete refusals can also be retried, and **Open novel / keyword** selects the novel and searches the coloring tab for the parent keyword; discarding lists and drops the changes made under the item, and focus moves to the next card. Conflict tables show category and nature names, chapters and image thumbnails. Every card in the coloring, replacing and settings lists shows its sync state ("Pending", or "Needs attention", which opens the page), and deleting a keyword created offline says how many unsent changes under it go too.

Downloads go through the background (`downloadNovel`): it pins the novel and pulls it under the lock. Removing a download with unsynced changes opens a dialog (**Sync now**, **Discard changes and remove**, **Cancel**); removal checks the outbox in the database transaction and refuses to discard another account's changes, prompting the reader to sign in to that account; a novel removed on the server shows a banner offering to remove it. Novels, slugs, website selectors and chapter biases are online-only (decision D6): their actions are disabled offline with an explanation, and after an online save the runner pulls the novel again. Images attached or generated in character forms are kept on the device (up to 10 MB each) and uploaded with the change; page tooltips show them once uploaded. If IndexedDB cannot be opened (for example Firefox with site data blocked), the popup shows a banner, lists and page highlighting read straight from the API, and edits are refused with that reason (they could not be kept).

Updating from 3.2.x deletes the old `storylens-offline` database and `storylens-sync-state` pool without reading them: novels must be downloaded again, and changes that had not synced before the update are lost (decisions D13, D14).

Run the extension tests with `bun run test` (or `make test`) from `apps/extension`; they use a fake browser, `fake-indexeddb` and an in-memory API that follows the sync contract (`test/helpers/`), and `test/ui/` renders components with happy-dom and Testing Library.

Browser-dependent tests share the `#imports` mock from `test/helpers/fake-browser.ts`. Override methods on that shared browser only for the tests that need them, and restore them after each test. Replacing `#imports` with a partial browser mock leaks into later files in the same Bun process and breaks UI and offline tests.

## Usage analytics

The extension sends pseudonymous Google Analytics 4 events through the Measurement Protocol from the background service worker; Manifest V3 forbids remotely hosted code, so `gtag.js` is not used. ## Initial chapter ranges and highlight effects

**Keyword/alias forms → Advance** is collapsed by default at the end of the form, after the image. The add-keyword form also includes chapter ranges. Starting chapter defaults to 0; an empty ending chapter means no end. Values must be whole nonnegative numbers and the end cannot precede the start. The range belongs to the initial version and saves offline through the outbox. Existing range edits remain moderator-only. A later version starts after the latest version’s start; an explicit earlier end is preserved. Highlighting stays visible outside explicit ranges using the nearest earlier version, or the base before any version starts.

**Keyword/alias forms → Advance → Word VFX** adds decoration over the existing highlight: **None** (default) uses the category’s effect, or keeps normal highlighting when the category has none; **Sparkles** shows eight frequently staggered word-colored stars that rise and fade; **Heat** ripples the word with faint rising smoke; **Shaking** uses an angled horizontal tremor with short pauses; **Glitching** briefly tears the glyphs into pixels with masked cyan/magenta bands and neon fringes. **Settings → Appearance → Show word VFX** is off by default, even for words with a saved effect. Turning it on or off updates existing highlights in every open reading tab immediately without rebuilding their text; the local boolean preference is saved as `storylens-show-category-effects`. Category color and the nature marker remain visible with every choice. Explicit effects belong independently to each keyword or alias (`wordVfx`); None on an alias does not inherit its keyword’s effect. The same control appears in create and edit forms, syncs offline and treats missing/unknown cached values as None. **Heat** and **Sparkles** also show **Word VFX color**. Clearing the picker restores inheritance. Custom tints sync offline, survive visibility changes and do not recolor the word’s text or nature marker. Other effects have no picker. **Settings → Categories** exposes the same effect/tint controls for moderators. Category `wordVfx`/`wordVfxColor` supplies the default when a word is set to None. A non-None keyword or alias effect uses its own tint (or current highlight color), with no category tint fallback. The visibility preference retains its existing storage key to preserve saved choices. Reduced motion and forced colors keep plain highlighting. Decorative elements contain no text and preserve Arabic joining, copying and tooltips. Only words in or just beside the viewport animate. While scrolling, animations and shared SVG filters pause and resume 150ms after scrolling stops; offscreen words and hidden tabs do no animation work. Reduced motion and forced colors also pause the SVG filters. Tracking is cleaned up when VFX are disabled or highlights are rebuilt.

## Chapter cover images

Refreshing during cover generation no longer requires its owner to wait for the 30-minute lease. Generate/Regenerate (or the launcher action) can explicitly restart the same reader's unfinished attempt. The existing image remains visible during a replacement. Automatic loading and polling do not restart active jobs; other readers still wait. The extension sends the observed reservation revision when restarting, so simultaneous or stale tabs cannot replace a newer attempt, and old attempts cannot publish over or cancel the replacement. Older servers without restart support retain the waiting behavior.

The launcher action beside Summary is **Generate Chapter Cover Image**. A shared cover displays immediately before chapter content on every visit. Checking for a saved cover and passively waiting for another reader’s cover add no placeholder or controls to the DOM; the image appears when found. Explicit generation keeps its progress and Stop controls. Extension Settings → AI includes **Auto Generate Chapter Cover**, off by default; its shared image template is edited in dashboard Settings → AI. Enabling it generates a missing cover when a detected chapter loads using the selected image provider (Desktop/Codex or Story Lens Cloud); Cloud uses the displayed lens price. It never regenerates an existing cover. The default prompt requests a wide 16:9 landscape image and preserves the administrator’s configured composition. Every new cover waits for the current chapter’s valid published context, including an in-progress replacement, before reserving artwork or calling the image provider. While waiting, progress and Stop remain available. Missing context shows guidance to generate it in the chapter-context section; it never silently starts a separately billed context request. Once ready, the prompt selects the single most valuable scene (turning point, conflict, revelation or emotional moment) from context and chapter text together. Each depicted element uses that scene’s appearance, condition, clothing, equipment, pose, emotion, relationships and environment; chapter text resolves conflicts. It never merges unrelated moments or imports another scene’s temporary or later state. Stored novel context provides background; bilingual mentioned keywords/aliases provide identity descriptions and image references independently of the highlighting filter. Context serialization retains all scene overviews and whole observations within its budget, and the complete prompt stays within 180,000 characters. Cloud and supported desktop clients also receive visual references.

`src/lib/chapter-cover/` prepares the prompt, renders a bare image with no title, card, border, padding or close button, and sends typed background requests. The image fills the available width immediately before the chapter content, preserving its original aspect ratio with automatic height and no cropping or height limit. A three-dot disclosure at the top inline-end corner fades in on hover or keyboard focus, stays accessible on touch, and respects reduced motion. Its actions include **Copy image prompt**, **Regenerate background image**, **Download image** and **Stop** during generation; Escape or an outside click dismisses the menu. **Stop** cancels generation; an upload failure preserves the local preview for download and **Save cover**. Covers are shared online data on Chapter, keyed by novel ID and chapter number; artwork URLs come from its File reference. Readers reserve a missing cover before generating, upload the result and publish it; competing tabs/readers wait for that cover. Guests can view covers, registered readers can generate them. Navigation or page disposal releases unfinished claims and prevents late results from changing the next chapter. Failed generation and saving retry automatically until successful or stopped, starting after 2 seconds and backing off to at most 60 seconds between attempts. Saving retries reuse the generated image and stable upload ID. Stop, navigation and disabling automatic generation cancel retry delays as well as active work. Regeneration preserves the current image until a replacement is ready and uses an explicit owned claim; only its publisher or a moderator may replace saved artwork. Automatic failure does not open a billing page or switch providers.

## Structured chapter context

The context publisher and moderators can manually edit parsed properties in the Chapter context disclosure. A pencil appears beside each property on hover or keyboard focus and stays available on touch. Clicking it opens the current value with Save (checkmark) and Cancel (X) icons. Text fields edit strings, multiline strings use a textarea, and collection fields accept JSON while individual list values can be edited directly. Save validates and persists the shared context without AI or lens charges; Cancel/Escape discards the draft. Incoming records and failed/stale saves preserve an open draft; after a conflict, Cancel loads the latest version before another edit. Generation and competing edits are locked while editing. Other readers and older servers remain read-only. Recently absent entity metadata is derived from earlier chapters and remains read-only here. Successful manual saves emit only the `chapter_context_edited` usage event, without chapter contents or property data.

**Settings → AI → Auto generate chapter context** is off by default. When enabled, opening a detected chapter creates context only for a chapter that has no saved context using the selected text AI provider and displayed lens price. It saves JSON containing a short summary, ordered scenes, environments, entity observations and explicitly established lasting changes. Generated output is validated before saving; source hashes and shared reservations prevent repeated work. Automatic generation always reuses existing valid context, even if its source hash is missing or the page text changed. A missing context generates on each newly opened detected chapter, independently of whether a cover exists. Only explicit replacement requests from the publisher or a moderator can replace saved context. Generation reads current chapter text, using one earlier context plus bulk-restored returning elements for established visual continuity. It preserves scene chronology and never assumes healing/repair from absence. Oversized chapters are refused rather than summarized incompletely. Stop and navigation cancel the task and release its reservation.

The light **Chapter context** text below a background image expands a structured readable view, including scenes, character/item states, evidence and recently absent entities. When a context exists without artwork it appears before chapter text. This uses a native disclosure, supports English/Arabic and dark mode, and renders all content as text. Its generation button becomes **Regenerate context** once context exists and retains the selected Cloud price. Explicit regeneration bypasses source-hash reuse while preserving publisher/moderator replacement permissions. Failed generation and publication retry with the same cancellable backoff as artwork; publication retries reuse validated output rather than requesting another AI response. The existing context remains readable throughout regeneration. Unregistered entities are included too; registered keywords and aliases resolve to canonical keyword IDs.

Reading a chapter requests only its own context. Normal context-generation tracking fetches exactly one nearest ready earlier chapter; use N−1 when available and otherwise the closest earlier published context. `contextHistory` uses the guarded background transport’s POST `…/tracking`, which returns the predecessor and small last-seen pointers. Match returning names locally, including Arabic marks/aliases; do not send chapter text to these read endpoints. For elements actually returning now and last seen outside that predecessor, deduplicate their earlier source chapter numbers and make one POST `…/bulk` request, with relevant entity keys. Do not bulk-load absent elements, fetch next chapters, crawl chapter pages or automatically generate history. History is loaded only before a new AI context request, not on passive visits or publication retries. Older APIs/offline failures preserve chapter-only generation without falling back to the future-reading legacy endpoint.

`withImageContinuity()` uses the same one-predecessor/returning-elements path while preparing character-image source material. Copying uses the existing image description without loading continuity. Initial cover source preparation requires the ready current chapter context; regeneration from an existing edited description and copying a saved description do not prepare context again. `continuitySection` filters future chapters, future last mentions and future state facts even if a stale provider returns them; keep bounded valid JSON and whole relevant observations. Earlier visual facts may persist until contradicted, while earlier scene pose/mood/location cannot establish current state. Only current scene membership/actions/new changes are recorded.
