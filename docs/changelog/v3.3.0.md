# Story Lens v3.3.0 (offline-first)

**Status:** Unreleased — the offline-first release. The version number is a placeholder for the next release after `v3.2.1`; any bump works, because the API refuses every client up to 3.2.1. Ship all four apps together ([release order](../../offline-first-refactor-plan/10-rollout-hardening-and-docs.md#release-order)).

## Reliable offline editing

- Changes are saved on the device first and sent by the background, online or offline: closing the popup, restarting the browser or losing the connection no longer loses edits.
- Changes sync in order, are never duplicated, and merge automatically when someone else edited other fields. When the same field changed on both sides, or a change can no longer apply, it waits under **Sync status** with clear choices (keep mine, use theirs, edit, create again, discard).
- The navbar always shows sync state, the last sync time and **Sync now**. Changes made while signed in as another account are kept apart and never sent with the wrong account.
- Pages show novels you have not downloaded straight away and refresh them in the background. Downloaded novels stay fresh by downloading only what changed.
- Images can be added offline; they upload when the connection returns.
- Adding, editing and deleting novels, slugs, website selectors and chapter biases need a connection and are disabled offline.
- Readers can edit and delete the aliases and versions they added, including under another reader's keyword.
- Names with apostrophes and quotes (for example D'Artagnan) now highlight correctly after syncing.

## After updating

- **Download your novels again for offline use.** The update starts a fresh offline store; changes made offline and not yet synced when the update arrives are not kept.
- **Update the desktop client.** Older extensions and desktop clients are asked to update before they can talk to Story Lens.

## API, dashboard and desktop client

- Synced reader routes take client IDs, detect stale writes, answer machine-readable error codes, accept partial updates and clears, and provide change feeds for delta sync (`GET /api/user/sync/…`).
- Aliases are named in Arabic and English like keywords; the dashboard's alias form edits both names.
- Stored text is kept exactly as typed.
- The desktop crawler sends client IDs and treats names that already exist as saved.
